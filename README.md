# StudyGit

> A Git-inspired collaborative study planner for students. Publish syllabus roadmaps, fork them to personalize your study schedules, and propose resource improvements via pull requests.

---

## Prerequisites

- **Node.js**: v18.0.0 or higher (v24.x tested)
- **npm**: v9.0.0 or higher
- **MongoDB**: Local MongoDB instance (`mongodb://localhost:27017/studygit`) or MongoDB Atlas connection string URI.
  *(Note: The server will boot and serve `/api/health` without MongoDB, but `/api/roadmaps` database endpoints require an active MongoDB connection).*

## Getting Started

### 1. Backend Setup

1. Open a terminal in the `server` directory:
   ```bash
   cd server
   ```

2. Install backend dependencies:
   ```bash
   npm install
   ```

3. Create your `.env` configuration file from the template:
   ```bash
   copy .env.example .env
   ```
   *(On macOS / Linux use `cp .env.example .env`)*

   Default variables:
   ```env
   PORT=5000
   MONGODB_URI=mongodb://localhost:27017/studygit
   CLIENT_URL=http://localhost:5173
   ```

4. Start the backend development server:
   ```bash
   npm run dev
   ```
   The backend will start at `http://localhost:5000`.

5. Run automated backend tests:
   ```bash
   npm test
   ```

---

### 2. Frontend Setup

1. In a separate terminal, open the `client` directory:
   ```bash
   cd client
   ```

2. Install frontend dependencies:
   ```bash
   npm install
   ```

3. Start the Vite development server:
   ```bash
   npm run dev
   ```
   The frontend will run at `http://localhost:5173`.

## Roadmap Data Model

The `Roadmap` entity represents a structured course syllabus curriculum graph:

### Schema Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `title` | String | Yes | Name of the syllabus roadmap (e.g., "Data Structures & Algorithms") |
| `subject` | String | Yes | Subject or academic field (e.g., "Computer Science") |
| `description` | String | No | Detailed syllabus overview and learning outcomes |
| `university` | String | No | Associated college or institution |
| `semester` | String | No | Academic term or semester |
| `tags` | Array of Strings | No | Searchable keywords (e.g., `["dsa", "algorithms", "cs"]`) |
| `visibility` | Enum | No | `"public"` (default) or `"private"` |
| `ownerId` | ObjectId | No | Reference to future User document |
| `modules` | Array of Subdocs | No | Embedded curriculum modules (see below) |
| `parentRoadmapId`| ObjectId | No | Upstream roadmap reference for future forking support |
| `version` | Number | No | Version counter (default `1`) |
| `createdAt` / `updatedAt` | Date | Auto | Timestamps generated by Mongoose |

### Subdocument Hierarchy

```text
Roadmap
└── modules: [
      {
        title: String (Required),
        description: String,
        order: Number,
        topics: [
          {
            title: String (Required),
            description: String,
            estimatedHours: Number (>= 0),
            order: Number,
            resources: [
              {
                title: String (Required),
                url: String (Required, valid http:// or https:// URL),
                type: Enum ("video", "article", "pdf", "documentation", "other"),
                description: String
              }
            ]
          }
        ]
      }
    ]
```

## API Endpoints

### System Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/health` | Health check returning API operational status, uptime, and database state |

### Roadmap Endpoints

| Method | Endpoint | Description | Query Parameters |
|---|---|---|---|
| `GET` | `/api/roadmaps` | List public roadmaps | `page`, `limit`, `subject`, `university`, `semester`, `tag`, `q` / `search` |
| `GET` | `/api/roadmaps/:id` | Retrieve single roadmap by ID | None |
| `POST` | `/api/roadmaps` | Create a new roadmap | None (JSON payload) |
| `PATCH` | `/api/roadmaps/:id` | Update permitted roadmap fields | None (JSON payload) |
| `DELETE` | `/api/roadmaps/:id` | Delete a roadmap by ID | None |

> **Security Note:** In this development phase, roadmap write endpoints (`POST`, `PATCH`, `DELETE`) are open for rapid testing and prototype development. In production, these endpoints must be protected behind authentication and authorization middleware. Client-supplied `ownerId` is not verified as proof of ownership until user authentication is introduced.

## API Examples

### 1. Create a Roadmap (`POST /api/roadmaps`)

**Request:**
```http
POST /api/roadmaps HTTP/1.1
Host: localhost:5000
Content-Type: application/json

{
  "title": "Data Structures & Algorithms",
  "subject": "Computer Science",
  "description": "Core computer science curriculum covering linear and non-linear data structures, trees, and graphs.",
  "university": "State Technical University",
  "semester": "Semester 3",
  "tags": ["dsa", "algorithms", "computer-science"],
  "visibility": "public",
  "modules": [
    {
      "title": "Module 1: Linear Structures",
      "description": "Linked Lists, Stacks, and Queues",
      "order: 1,
      "topics": [
        {
          "title": "Singly and Doubly Linked Lists",
          "estimatedHours": 4,
          "order": 1,

            {
              "title": "Linked List Visualizer",
              "url": "https://visualgo.net/en/list",
              "type": "documentation",

        }
      ]
    }
  ]
}
```

**Response (`201 Created`):**

{

## Testing

Backend test suites are implemented with Node.js's built-in test runner (`node --test`), requiring no heavy third-party testing dependencies:

```bash
cd server
npm test
```

### What is tested:
1. **Schema Validation (`roadmapModel.test.js`)**:
   - Valid roadmap document passes validation.
   - Missing required fields (`title`, `subject`) trigger validation errors.
   - Invalid `visibility` enums are rejected.
   - Malformed/non-HTTP resource URLs are rejected.
   - Invalid resource type enums are rejected.
   - Negative `estimatedHours` values are rejected.
2. **Middleware (`middleware.test.js`)**:
   - `validateObjectId` blocks malformed IDs with `400 Bad Request`.
   - `validateObjectId` passes valid 24-char hex ObjectIds.
   - `checkDbConnection` yields `503 Service Unavailable` when MongoDB is disconnected.
   - `errorHandler` formats malformed JSON bodies as `400 Bad Request`.
3. **Controller Logic (`roadmapController.test.js`)**:
   - `getRoadmapById` returns `404 Not Found` for nonexistent documents.
   - `getRoadmapById` returns `403 Forbidden` for private roadmaps.
   - `updateRoadmap` strips protected fields (`version`, `ownerId`, `parentRoadmapId`, `createdAt`, `updatedAt`).
   - `deleteRoadmap` returns `404 Not Found` when trying to delete missing documents.
